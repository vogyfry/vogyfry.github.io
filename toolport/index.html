Your Agent Is Drowning in Tool Definitions

Every MCP server dumps its whole tool menu into the agent's context. A few servers together can eat 40–50% of the window before any work starts. Toolport fixes that with progressive disclosure.

🔍

Semantic Tool Search

The agent describes what it wants to do — "turn off the broken approval flow" — and Toolport returns the top matching tools from across all your servers. Three meta-tools replace hundreds of definitions, saving ~80% of the tokens.

🌍

Any Language In, Any Language Out

Cross-lingual embeddings mean a query in Japanese finds a tool described in English, and vice versa. Most tool layers are English-only; Toolport is multilingual by architecture.

🏠

Local-First

The search index and embedding model live on your machine. Discovery works offline, round trips stay on-device, and nothing about your tools is sent to a cloud service.

🤝

Agent-Agnostic

Works with any MCP-speaking client — Claude Code, Codex, Cursor, or your own agent. One registry entry replaces a page of server configs, and Toolport teaches connecting agents the workflow automatically.

🔐

Hosted Servers, OAuth Built In

Connect remote MCP servers over HTTP with sign-in handled for you — including enterprise services like Microsoft 365 and GitHub. One-click Sign In per connector; tokens are stored locally, never proxied through us.

🧩

First-Party Connectors, Bundled

Seven "Prava for …" connectors ship inside the app — Power Platform, Microsoft 365, Apple, Apple Docs, Markets, Reddit, Google Workspace. Discrete tools, structured output, confirm-gated writes. Only available with Toolport.

📊

Menu-Bar Command Center

A native macOS menu-bar app supervises everything: add servers from a catalog or by hand, watch the live savings receipt, edit policy gates, re-index on demand, and run diagnostics — no terminal required.

More Than Routing: Built-In Modules

Tool bloat is one firehose — Toolport's modules close the rest. All run inside the same local engine, on every plan, and each can be tuned or switched off in Settings.

🧾

Trace — The Savings Receipt

Every search is metered: what loading your full catalog would have cost vs. what the agent actually received. The receipt lives in the menu bar and in a get_savings call — proof, not promises.

🛡️

Policy — Gates Before Anything Runs

Read-only mode, dry-run, allow/deny lists, and confirm-to-send for outbound actions — one config protects every connector. A send that wasn't approved with its exact arguments doesn't run. Safety is never paywalled.

✂️

Results — Outputs, Condensed

Oversized tool outputs (logs, JSON dumps, tables) arrive condensed with nothing lost — the full payload stays retrievable page by page. Never silent truncation.

📖

Retrieve — Passages, Not Pages

Agents call search_context and the fetch-and-extract happens in the engine: web pages and your local docs come back as a few cited passages. The 40k-token page never enters the prompt. Bring-your-own search key optional.

♻️

Cache — Don't Pay Twice

A repeated read-safe call — even paraphrased, even in another language — serves the prior result and skips the downstream call. Only tools that declare themselves read-only are eligible; approved actions never cache.

🧠

Memory — Facts That Persist

Agents store durable facts explicitly (remember / recall / forget) with provenance and expiry. Recall is semantic and cross-lingual: a fact stored in English is found by a Japanese query. Everything stays on your machine, with a viewer in Settings.

⚖️

Grounding — Trust the Right Sources

Retrieved passages carry trust tiers, cross-source corroboration counts, and duplicate collapse — so agents can tell documentation from SEO spam before quoting it.

Set Up in Minutes

One install. One registry entry in your agent. Done.

1

Install Toolport

Toolport lives in your menu bar and runs the registry engine locally — a native app for Mac and Windows.

2

Add Your MCP Servers

Pick servers from the built-in catalog or add your own. Toolport connects to each one, asks for its tools, and files everything into a local searchable index.

3

Point Your Agent at Toolport

Register Toolport as a single MCP server in Claude Code, Codex, Cursor, or any MCP client. That one entry now fronts every server you added.

4

Work Normally

Your agent discovers tools on demand — search, load one schema, invoke. When a server's tools change, Toolport re-checks it automatically.

Progressive disclosure beats loading everything up front.
