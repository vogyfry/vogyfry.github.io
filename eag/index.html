Any API, in the language of agents

Enterprise systems speak REST, SOAP, OData. Agents speak natural language. EAG is the layer in between — one canonical, plain-language tool catalog fronting every backend, governed on every call.

🗂️

One Canonical Tool Catalog

A single, stable, natural-language contract agents route on. EAG maps each canonical tool to the right backend call — and matching works across languages, so a query in German finds a tool described in English.

🔐

Identity-Aware, Per User

Entra SSO in, OAuth On-Behalf-Of downstream. Every call runs as the signed-in user — never a shared service account — so each backend's own row-level security still applies underneath.

🛡️

Governed by Tier

Read / write / privileged tiers with policy gates: confirm-before-write, privileged actions blocked or approval-gated. The agent can't do more than the caller's role allows.

🧾

Audited End to End

Every call recorded — user, tool, system, outcome, latency. A ready-made compliance trail and seat-metering feed, exportable to your SIEM. The audit is the proof, not a vibe.

🔌

Manifest-Driven Backends

Add a system with a manifest and the console's Connect dialog — validate before you enable. Or federate any system that already speaks MCP, with zero driver code.

♻️

Migration Insurance

You license the catalog, not the backends. Swap ServiceNow → Jira or SAP ECC → S/4HANA one tool at a time, with a rollback toggle and an audit trail — and your agents never change.

🖥️

Admin Console Built In

One signed-in console runs the whole estate: flip systems on and off, connect backends with validate-before-enable, author tool-to-table mappings against live metadata, watch every call stream in, and manage user roles — no YAML required for day-two ops.

🔎

Identity Probe

Answer "what would this user see?" before they ask. Probe any scope set and get the exact tool list that identity would be served — allowed, gated, or hidden, with the policy reason — governance you can demonstrate, not assert.

Stand It Up in Your Own Tenant

One image, config per customer. Single-tenant, self-hosted — your systems never leave your cloud.

1

Run the Container

Docker → Azure Container Apps, App Service, on-prem, or air-gapped. One governed image; the tier is unlocked by an offline license key.

2

Connect Your Identity

Point EAG at your Entra tenant. Admins sign in to the console over OIDC; agent callers present real tokens, exchanged per-user via OBO downstream.

3

Connect Your Systems

Wire each backend from the Connect dialog or a manifest — validate before enabling. Federate anything that already speaks MCP. Set gating and rate limits per system.

4

Point Your Agents at It

Register EAG as one MCP endpoint in Copilot Studio, Azure AI Foundry, Claude, or any MCP client. That single entry now fronts your whole governed fleet.

EAG vs. Wiring Agents to Systems Directly

A governed layer beats point-to-point integrations that multiply with every agent.

Identity ✗ Shared service account — everyone is "the app" ✓ Per-user OBO — every call runs as the signed-in user
Governance ✗ Whatever the raw API allows ✓ Tier gates, confirm-to-write, privileged blocked
